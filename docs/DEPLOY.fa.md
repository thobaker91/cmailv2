## پیش‌نیازها

- یک **حساب Cloudflare** — پلن رایگان کاملاً کافی است (Workers، D1، Email Routing و کرون همه داخل همین است).
- برای مسیرهای ترمینالی: **Node.js نسخهٔ ۱۸ به بالا**.
- برای دریافت ایمیل: یک **دامنه روی حساب Cloudflare** (هر Zoneای — ویزارد، فعال‌کردن Email Routing را قدم‌به‌قدم راهنمایی می‌کند).

## مسیرت را انتخاب کن

| مسیر | سبک | زمان | چه چیزهایی دستت می‌خورد |
|---|---|---|---|
| **۰ — یک کلیک** | مرورگر، با دکمه | ~۲ دقیقه | دکمهٔ **Deploy to Cloudflare** پایین را فشار بده |
| **۱ — یک دستور** | ترمینال، خودکار | ~۳ دقیقه | `bash deploy.sh` همه‌چیز را می‌کند |
| **۲ — کاملاً گرافیکی** | فقط مرورگر، بدون حتی یک دستور | ~۷ دقیقه | داشبورد: ساخت دیتابیس → جای‌گذاری ورکر → یک Binding |
| **۳ — ترمینال، قدم‌به‌قدم** | دستی، شفاف | ~۵ دقیقه | دستورهای wrangler |

## راه ۰ — یک کلیک (دکمهٔ Deploy)

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/Erfan-8910/Cmail)

دکمه را فشار بده و بقیه‌اش با Cloudflare است — کلون، ساخت منابع و دیپلوی، همه خودکار:

1. **دکمه را فشار بده** — کلادفلر ریپو را داخل گیت‌هاب خودت کپی می‌کند، یک **دیتابیس D1 تازه** می‌سازد، بایندینگش را وصل می‌کند و Worker را دیپلوی می‌کند. (برای اینکه دکمه ریپو را ببیند، ریپو باید Public باشد.)
2. **برو داخل برنامه** — روی آدرسی که کلادفلر نشان می‌دهد؛ `/setup` کار را می‌گیرد: ساخت حساب مدیر.
3. **دامنه‌ات را وصل کن** — ویزارد، فعال‌کردن Email Routing روی Zone خودت را قدم‌به‌قدم راهنمایی می‌کند (دریافت ایمیل همیشه داخل کلادفلرِ خودت زندگی می‌کند؛ پس دامنه باید در همان حساب باشد).
4. کد، دست خودت است: دکمه، پروژه را همراه یک پایپ‌لاین CI داخل گیت‌هاب خودت گذاشته — هر push دوباره می‌سازد و دیپلوی می‌کند.

راه‌های بعدی هم دقیقاً مثل قبل سر جایشان‌اند — برای نصب دستی و سلیقه‌های ترمینالی.

## راه ۱ — یک دستور (ترمینال)

```bash
git clone https://github.com/Erfan-8910/Cmail.git
cd Cmail
bash deploy.sh
```

نصب‌کننده همه‌چیز را انجام می‌دهد: دیتابیس D1 را می‌سازد، جدول‌ها را اعمال می‌کند، یک `APP_SECRET` قوی و تصادفی می‌سازد، Worker را دیپلوی می‌کند و در آخر آدرس پنل را چاپ می‌کند. صفحهٔ راه‌اندازی که باز شد، از آن‌جا به بعد خودش ادامه می‌دهد.

## راه ۲ — کاملاً گرافیکی، بدون حتی یک دستور

پنج قدم. بدون SQL، بدون آپلود پوشه — فقط مرورگر تو و داشبورد Cloudflare.

**۱) دیتابیس را بساز**

- وارد [dash.cloudflare.com](https://dash.cloudflare.com) شو → **Storage & Databases → D1 SQL Database → Create**
- اسمش را بگذار `cmail-db` و بساز. همین — از این به بعد ساختن جدول‌ها کار خود Cmail است.

**۲) Worker را بساز و کد را جای‌گذاری کن**

- **Workers & Pages → Create → Workers → Create Worker**
- اسمش را بگذار `cmail` و یک بار با کد پیش‌فرض **Deploy** کن.
- **Edit code** را بزن، کد پیش‌فرض را پاک کن، محتوای کامل [`worker.js`](https://github.com/Erfan-8910/Cmail/releases/download/v3.0.0/worker.js) آماده را جای‌گذاری کن و **Deploy** بزن.

**۳) تنها Binding مورد نیاز: D1**

- برگرد به Worker: **Settings → Bindings → Add**
- نوع **D1 database** → نام متغیر: `DB` → دیتابیس: `cmail-db` → Save / Deploy.
- (اختیاری ولی توصیه‌شده) یک **Secret** هم اضافه کن: نام `APP_SECRET` → مقدار: یک رشتهٔ تصادفی بلند. این کلید رمزنگاری داخلی برنامه است — یک بار بساز، دیگر تغییرش نده.

**۴) پاک‌سازی خودکار را زمان‌بندی کن**

- **Settings → Trigger Events → Cron Triggers → Add** و وارد کن: `17 * * * *`

**۵) تمام — آدرس Worker خودت را باز کن**

- اول **مرحلهٔ D1** باز می‌شود: همهٔ جدول‌های مورد انتظار با وضعیتشان. هر چه کم است با یک دکمه ساخته می‌شود — تک‌تک یا یک‌جا — و جدول‌های ناشناخته دکمهٔ حذف تمیز دارند (جدول‌های اصلی محافظت می‌شوند).
- بعد **نام کاربری و گذرواژه** انتخاب می‌کنی — از این به بعد همین‌ها کلید تو هستند.
- بعد **ویزارد دامنه** خودش باز می‌شود و ارسال ایمیل هم همان‌طور که هست — یک بونوس اختیاری با دکمهٔ تست.

> 💡 میان‌بر: در **Workers & Pages → Create** می‌توانی به‌جای همهٔ این‌ها فورک GitHub خودت را وصل کنی (Connect to Git) و بگذاری Cloudflare خودش بسازد. فقط اول `REPLACE_WITH_D1_ID` در `wrangler.jsonc` را با شناسهٔ واقعی دیتابیس عوض کن.

## راه ۳ — ترمینال، قدم‌به‌قدم

<details open>
<summary><b>برای آدم‌های ترمینال</b></summary>

```bash
git clone https://github.com/Erfan-8910/Cmail.git
cd Cmail
npm install
npx wrangler login

npx wrangler d1 create cmail-db
#   شناسهٔ database_id برگشتی را در wrangler.jsonc بگذار (REPLACE_WITH_D1_ID)
npx wrangler d1 migrations apply cmail-db --remote
npx wrangler secret put APP_SECRET     # یک رشتهٔ تصادفی بلند
npx wrangler deploy
```

مسیر CLI جدول‌ها را به‌شکل مایگریشن اعمال می‌کند (`0001` تا `0005`)؛ اگر همه را یک‌جا می‌خواهی: `npx wrangler d1 execute cmail-db --remote --file=schema.sql`.

بعد در داشبورد: دامنه‌ات → **Email → Email Routing** → فعالش کن → **Catch-all address → Action: Send to Worker → cmail**.

</details>

## ساخت دستی جدول‌ها — فقط یک فایل، ضدخطا

<details>
<summary><b>اگر خواستی جدول‌ها را دستی از داشبورد بسازی</b> (باز کن)</summary>

اگر لازم شد اسکیمای دیتابیس را بیرون از برنامه بسازی، دقیقاً یک فایل وجود دارد: [`schema.sql`](../schema.sql). چرا این فایل امن است و فایل‌های قدیمی نبودند:

- **کامنت‌هایش نه نقطه‌ویرگول دارند و نه گیومه** — همان چیزی که جداکنندهٔ دستور Console را گمراه می‌کرد و گزارش‌های «خطا می‌دهد و وارد نمی‌شود» را می‌ساخت؛
- **همهٔ دستورهایش `IF NOT EXISTS` دارند** — روی دیتابیس تازه، نیمه‌کاره یا کامل، دوباره paste کردنش هیچ‌وقت خطا نمی‌دهد؛
- شکل نهایی هر ۱۱ جدول و ۱۵ ایندکس را دارد، ستون‌های چرخهٔ حیات دامنه هم شامل می‌شود.

از داشبورد اجرایش کن: **Storage & Databases → D1 → cmail-db → Console** → کل فایل را paste کن → Execute. تمام. وسط کار قطع شد؟ دوباره paste کن — از همان‌جا که مانده ادامه می‌دهد.

```bash
npx wrangler d1 execute cmail-db --remote --file=schema.sql
```

⚠️ فایل‌های پوشهٔ `migrations/` فقط برای ترمینال هستند (سربرگشان هم گفته) — در Console پیست‌شان نکن. دستورهای `ALTER`شان روی دیتابیسِ ازقبل-مهاجرت‌شده خطا می‌دهند و کل بچ را متوقف می‌کنند.

</details>

## دامنه‌ها: از «افزودن» تا «تأیید شده»

هر دامنه مسیر روشنی را می‌پیماید — با ویزاردی که هر لحظه می‌توانی رهایش کنی و بعداً ادامه بدهی:

1. **افزودن** — دامنه یا زیردامنه را در پنل دامنه‌ها (یا صفحهٔ راه‌اندازی) بنویس، مثلاً `mail.yourdomain.com`، و Add بزن.
2. **اتصال** — ویزارد قدم‌به‌قدم سمت Cloudflare را می‌رود: فعال‌کردن Email Routing، نشستن خودکار رکوردهای MX، اشارهٔ Catch-all به ورکر. آخرش به دکمهٔ **«دامنه را وصل کردم»** می‌رسی.
3. **صحت‌سنجی** — یک کد یکتا می‌گیری؛ از هر صندوق شخصی که مال خودت است یک نامه به آن آدرس بفرست (موضوع و متن مهم نیست). صفحه هر چند ثانیه خودش را چک می‌کند؛ وقتی ورکر رسیدن نامه را تأیید کرد، دامنه سبز می‌شود.
4. **باز شدن** — از این لحظه ساخت صندوق روی دامنه — دائمی یا موقت — آزاد است.

در تمام مسیر دکمهٔ **خروج** هست و با زدنش می‌پرسد: *ذخیره به‌عنوان پیش‌نویس، یا خروج؟* پیش‌نویس‌ها در جدول دامنه‌ها با نشان «پیش‌نویس» می‌مانند و دکمهٔ «ادامه» ویزارد را از همان مرحله باز می‌کند. تا وقتی ثبت کامل نشده، ساخت صندوق روی آن دامنه قفل است — مگر اینکه خودت آگاهانه صحت‌سنجی را رد کنی و مسئولیتش را بپذیری.

هر دامنه یک نشان وضعیت زنده دارد: سالم، منتظر اولین نامه، منتظر صحت‌سنجی، پیش‌نویس، یا صحت‌سنجی‌نرفته. با فعال‌کردن Email Routing، خود Cloudflare این رکوردها را می‌سازد:

| رکورد | مقدار | توضیح |
|---|---|---|
| MX | `route1.mx.cloudflare.net` (اولویت ۱۰) | خودکار |
| MX | `route2.mx.cloudflare.net` (اولویت ۲۰) | خودکار |
| MX | `route3.mx.cloudflare.net` (اولویت ۳۰) | خودکار |
| TXT (SPF) | `v=spf1 include:_spf.mx.cloudflare.net ~all` | خودکار |

مهم‌ترین قدم آخر است: **Email Routing → Routing rules → Catch-all address → Action: Send to Worker → cmail**. از این لحظه **هر** آدرسی روی دامنه‌ات به Cmail می‌رسد.

## ارسال ایمیل — اختیاری، با تست واقعی

ارسال یک بونوس است، نه قفل: ردیفش در صفحهٔ راه‌اندازی برچسب **اختیاری** دارد و هیچ‌وقت میان تو و صندوقت نمی‌ایستد. وقتی خواستش: به **Brevo** (۳۰۰ نامه در روز رایگان) یا **Resend** (۱۰۰ در روز رایگان) وصل شو — حساب بساز، دامنهٔ فرستنده را آن‌جا تأیید کن، بعد در Cmail سرویس را انتخاب کن، کلید را بده و فرستنده را تنظیم کن. بعد **تست ارسال** را بزن: یک نامهٔ واقعی به هر آدرسی که بنویسی می‌رود و سیم‌کشی را همان‌جا ثابت می‌کند. کلید API فقط در D1 خودت ذخیره می‌شود — از Cloudflare تو بیرون نمی‌رود.

## ورود، دسترسی و رمزهای تو

پنل **تک‌کاربره** است؛ ثبت‌نامی در کار نیست و حساب دوم وجود ندارد. در اولین بازدید **نام کاربری و گذرواژه** انتخاب می‌کنی و از آن بعد همین‌ها تنها کلید تو هستند. اگر دوست نداری هر بار نام کاربری را تایپ کنی، در **تنظیمات → امنیت** گزینهٔ «ورود با نام کاربری» را خاموش کن — از آن بعد فقط گذرواژه کافی است.

امنیت جدی گرفته شده: گذرواژه‌ها با PBKDF2-SHA256 (۱۰۰ هزار دور) هش می‌شوند، نشست‌ها روی کوکی httpOnly می‌روند، خود حساب از TOTP دومرحله‌ای پشتیبانی می‌کند و تلاش‌های این‌همه‌ی ورود محدود نرخ می‌شوند.

### 🔑 اگر رمز یا نام کاربری را گم کردی

دنبال مستند نگرد — **راهنمای بازیابی همین‌جا، روی صفحهٔ ورود است**: زیر فرم، «راهنما و بازیابی حساب» را باز کن و دستورهای SQL آماده را کپی کن:

1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Storage & Databases → D1 → cmail-db** → تب **Console**.
2. **نام کاربری**‌ات را پیدا کن:

```sql
SELECT username FROM users;
```

3. **گذرواژه را ریست کن** به مقدار موقت `Recover-Cmail-2026`:

```sql
UPDATE users SET password_hash = 'pbkdf2$100000$Y21haWwtcmVjb3Zlci1zYWx0MQ==$lvVylyVdxsS9Ji19drxw9ko72vDhlyHCDf5dSIC9Z/c=' WHERE role = 'admin';
```

4. با نام کاربری و `Recover-Cmail-2026` وارد شو و **بلافاصله** در تنظیمات → امنیت گذرواژه را عوض کن. به هیچ نامه‌ای دست نمی‌خورد — این دستور فقط گذرواژه را عوض می‌کند.

> ⚠️ **هرگز `DELETE FROM users` نزن** — حذف کاربر آبشاری است و همهٔ صندوق‌ها و نامه‌هایش را پاک می‌کند. همان UPDATE بالا کافی است و گذرواژهٔ موقت را سریع عوض کن.

## ارتقا به نسخهٔ جدیدتر

- **راه ۲ (گرافیکی):** `worker.js` جدید را در Edit Code جای‌گذاری کن و Deploy بزن. اگر شکل دیتابیس جلو رفته باشد، پنل سلامت (تنظیمات → سلامت سامانه) پرچمش را می‌زند و دکمهٔ **ترمیم**ش ستون‌ها و جدول‌های جاافتاده را با یک فشار اضافه می‌کند — به داده‌هایت دست نمی‌زند. هندلر ایمیل ورودی هم تا زمانی که به ترمیم برسی روی دیتابیس قدیمی به تحویل ادامه می‌دهد، پس هیچ نامه‌ای سر راه گم نمی‌شود.
- **راه‌های ۱/۳ (ترمینال):** `git pull`، بعد `npx wrangler d1 migrations apply cmail-db --remote` و `npx wrangler deploy`.
